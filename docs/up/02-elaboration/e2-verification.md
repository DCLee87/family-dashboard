## 사설 HTTPS

- [x] NAS Tailscale을 공식 DSM 7 x86_64 패키지 `1.98.9`로 갱신
- [x] Mac과 NAS가 같은 Tailnet에서 직접 통신
- [x] Tailscale Serve가 HTTPS 443을 컨테이너의 loopback 8080으로 프록시
- [x] Serve 상태가 `tailnet only`임을 확인
- [x] Funnel 미사용
- [x] TLS 1.3 연결과 공개 신뢰 인증서 검증 성공
- [x] HTTPS 상태 API가 HTTP 200과 정상 DB 상태 반환
- [x] NAS LAN 주소의 8080 직접 연결 거부 확인
- [x] Wi-Fi를 끈 부모 모바일의 이동통신망에서 HTTPS 접속·새로고침 확인

공유기 포트 포워딩을 만들지 않았으며 DSM과 Container Manager를 인터넷에
공개하지 않았다.

복구 코드의 실제 값과 보관 위치는 기록하지 않는다. 사용자는 종이 또는
신뢰할 수 있는 비밀번호 관리자에 별도 보관한다.

정상 회전 실측에서는 신뢰 PC의 접근 자격 만료 시각만 시험용 과거 시각으로
변경한 뒤 HTTPS 페이지를 새로고침했다. 토큰 원문이나 해시는 조회하지
않았으며, 자격 종류·생성 시각·소비 및 폐기 여부와 보안 이벤트만 확인했다.
리프레시 자격 재사용 탐지는 신뢰 PC 전체를 즉시 로그아웃시키는 파괴적
시험이므로 NAS에서는 수행하지 않고 통합 테스트 결과로 확인했다.

공용 태블릿 시험에서는 Tailnet 전용 HTTPS URL에서 8자리 코드를 제출했다.
서버가 요청을 승인 대기 상태로 전환하지 않았고, DB의 요청은 미제출 상태로
남았으며 시험용 기기 레코드는 생성되지 않았다. 접근·리프레시 자격의 외부
거부는 통합 테스트로 확인했다.

LAN HTTPS는 `yong.local`의 별도 포트에서 Synology Reverse Proxy가
loopback 애플리케이션 포트로 전달한다. 공개 포트나 외부 DNS를 추가하지
않았다. 로컬 CA 공개 인증서를 Mac 로그인 키체인에 설치하고, CA 개인키는
AES-256 암호화 파일만 남겼다. 평문 CA·서버 개인키의 로컬 사본은 휴지통으로
이동했다. Mac 브라우저를 시험용 공용 태블릿으로 등록해 보기 모드와
독립 자격정보 발급, PIN 관리자 모드와 즉시 잠금을 확인했다. E2에는 실제
일정·할 일 편집 화면이 없고 기기 관리는 신뢰 PC 전용이므로, 공용 태블릿의
관리자 모드는 상태 문구와 잠금 버튼으로만 식별된다. 실제 태블릿은 Android
Chrome을 재시작한 뒤 LAN IP 기반 HTTPS에 경고 없이 접속했고,
`shared_tablet` 기기에 `local_only=1`과 독립 접근·리프레시 자격정보가
발급됐다.

신뢰 PC에서 의도적으로 잘못된 PIN을 5회 입력해 1~4회는 실패, 5회는
차단으로 기록되고 해당 기기에만 5분 `blocked_until`이 설정되는 것을
확인했다. 기기 인증과 보기 모드는 유지됐고 실제 공용 태블릿의 PIN 상태에는
영향이 없었다. 5분 경과 후 차단이 자동 만료됐으며 올바른 PIN으로 관리자
모드를 다시 열자 실패 횟수가 0으로 초기화되고 새 관리자 세션이 활성화됐다.

LAN 검증에 사용한 Mac 브라우저의 시험용 `shared_tablet` 레코드는 검증 후
폐기했다. 해당 브라우저는 즉시 미등록 상태로 전환됐고 활성 기기 목록에서
숨겨졌다. 실제 Android 공용 태블릿과 신뢰 PC는 활성 상태와 독립
자격정보를 유지했다.

새 공용 태블릿 등록 요청 한 건의 만료 시각만 시험용 과거 시각으로 변경한
뒤 LAN 등록 화면에서 코드를 제출했다. 서버는 만료 오류를 반환했고 요청을
제출 상태로 전환하지 않았으며 기기·자격정보도 생성하지 않았다. 실제 복구
코드는 현재 유일한 운영 복구 수단이므로 소비 시험을 수행하지 않는다.

## 남은 E2 실기기 시험

1. 복구 흐름 구현 후 복구 코드의 일회 사용과 재사용 거부를 실측한다.
2. NAS 재부팅 후 인증 쿠키, SQLite 무결성과 Serve 자동 복구를 확인한다.
3. 외부 백업 매체와 복구 절차를 구현하고 실제 복구 시험을 수행한다.
