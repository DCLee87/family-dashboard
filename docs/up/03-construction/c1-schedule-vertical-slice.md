# C1 일정 최소 수직 조각 계획

- 상태: 제안
- 작성일: 2026-07-29
- 목표 기간: 구현 시작 후 하나의 짧은 반복
- 기준: ADR-027, E4 일정 데이터 모델·유스케이스·추적표

## 반복 목표

등록된 관리자 PC에서 일회성 시간 일정을 저장하고, 부모 모바일과 공용
태블릿에서 권한에 맞는 오늘 일정과 일정 기반 가족 상태를 조회할 수 있는
최소 종단 흐름을 만든다.

이 반복은 전체 일정 기능을 한 번에 완성하지 않는다. DB 마이그레이션,
도메인 규칙, API와 최소 UI를 실제 NAS에 올릴 수 있는 한 조각으로
연결해 다음 반복의 주간 반복·예외 기반을 검증한다.

## 포함 범위

### 데이터베이스

- `family_members`와 아빠·엄마·딸 초기 행
- `schedules`, `schedule_participants`
- 일회성 `timed` 일정에 필요한 필드와 제약
- 공개 범위 `family`, `tv_summary`, `parents_only`
- 낙관적 동시성 버전과 생성·수정 기기 감사
- E3 운영 DB에서 안전하게 적용 가능한 새 migration

### 도메인

- UTC 저장과 `Asia/Seoul` 입력 변환
- `[start, end)` 검증과 겹침 검사
- 복수 대상 가족
- ADR-027 예상 상태 선택과 동률
- 권한별 상세·요약·비식별 DTO

### HTTP API

- `GET /api/v1/family-members`
- `POST /api/v1/schedules`
- `PUT /api/v1/schedules/{id}`
- `GET /api/v1/schedule-occurrences`
- `GET /api/v1/schedules/{id}`
- `GET /api/v1/family-status`

쓰기 API는 현재 E2 기기 인증과 관리자 모드를 재사용한다. 겹침 경고는
C1에서 확인 토큰을 만들지 않고, 첫 요청에 `confirmOverlap: true`를
명시해 재요청하는 단순 계약으로 시작한다. 토큰 방식은 실제 위변조 위험과
입력 비교 요구가 확인되면 C2에서 추가한다.

### 웹 UI

- PC·부모 모바일·공용 태블릿의 오늘 일정 목록
- 가족별 일정 필터
- 관리자 모드의 일회성 시간 일정 생성·수정
- 대상 가족 복수 선택과 공개 범위 표시
- 겹침 경고 확인
- 일정 기반 상태의 `일정 기준`, 종료 시각과 겹침 표시

## 제외 범위

- 매주 반복, 회차 변경·취소와 반복 원본 수정
- 종일·여러 날 일정
- 휴지통·복원·영구 삭제
- 일정 알림과 예약 작업
- 할 일, 공지, 날씨
- TV 전용 레이아웃과 3 m 실기기 시험
- 완전한 관리자 일정 관리 화면과 디자인 마감

제외 항목의 DB 확장을 막는 임시 구조를 만들지 않는다. C1 migration은
후속 테이블·필드를 추가할 수 있게 설계한다.

## 작업 순서

1. migration과 저장소 계약을 테스트 우선으로 작성한다.
2. 시간 구간·겹침·상태 선택·공개 투영 순수 함수를 작성한다.
3. 저장소 구현과 SQLite 트랜잭션 시험을 추가한다.
4. 읽기 API부터 연결하고 권한별 응답 계약을 고정한다.
5. 관리자 쓰기 API와 낙관적 동시성을 연결한다.
6. 최소 목록·입력 UI를 연결한다.
7. 기존 E2/E3 인증·PWA·Push 회귀 시험을 실행한다.
8. amd64 이미지를 만들고 NAS 적용 전 백업·되돌리기 절차를 준비한다.

## 자동화 완료 조건

- [ ] migration이 빈 DB와 E3 스냅샷 모두에 한 번만 적용된다.
- [ ] migration 재실행과 `--check-db`가 성공한다.
- [ ] 가족 구성원·일정 제약과 실패 트랜잭션 롤백을 검증한다.
- [ ] 시간 경계, 겹침과 ADR-027 동률 단위 시험이 통과한다.
- [ ] 부모·딸·태블릿·TV 공개 범위 응답 계약이 통과한다.
- [ ] 보기 모드와 만료 관리자 모드의 쓰기 요청이 거부된다.
- [ ] 오래된 버전 수정은 `409`이고 최신 데이터를 덮어쓰지 않는다.
- [ ] 웹 빌드, Go 테스트·빌드와 Docker amd64 이미지 빌드가 통과한다.
- [ ] 기존 기기 등록, 관리자 잠금과 Push 구독 시험이 회귀하지 않는다.

## 사용자 확인 완료 조건

- [ ] PC에서 일회성 시간 일정을 등록·수정할 수 있다.
- [ ] 폰과 태블릿에서 새 일정이 보이고 새로고침 후 유지된다.
- [ ] 대상 가족 필터와 복수 대상 일정이 기대대로 보인다.
- [ ] 공개 범위별 상세·요약·비식별 표시가 기대대로 보인다.
- [ ] 겹침 경고 후 저장과 일정 기반 상태를 확인한다.

## NAS 적용 게이트

다음 조건을 충족하기 전에는 운영 NAS DB에 migration을 적용하지 않는다.

1. 로컬·CI 자동화 완료 조건 통과
2. 배포 직전 SQLite와 설정 파일 백업
3. 현재 E3 이미지 태그와 compose 파일 보존
4. 새 migration이 이전 바이너리로 되돌릴 수 없는 경우 roll-forward 복구
   절차 문서화
5. 사용자가 NAS 배포 시점을 명시적으로 승인

## C1 이후 순서

1. C2: 주간 반복, 회차 변경·취소와 종일 일정
2. C3: 휴지통·복원, 일정 알림과 실시간/주기 갱신
3. C4: 할 일·회차·완료와 알림
4. C5: 공지·날씨·기기별 대시보드 통합

각 반복은 실행 가능한 이미지와 회귀 시험을 남긴다.
