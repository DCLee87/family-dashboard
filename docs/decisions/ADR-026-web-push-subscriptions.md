# ADR-026: 부모 모바일 Web Push 구독 기준선

- 상태: 승인
- 결정일: 2026-07-29

## 배경

부모 모바일 PWA는 사용자가 명시적으로 허용한 경우 일정·할 일·중요 공지
알림을 받아야 한다. Push endpoint와 구독 키는 알림을 보내는 데 필요한
자격정보이며 등록 기기 폐기와 함께 무효화해야 한다. 일정 공개 범위를
적용하기 전에는 실제 가족 내용을 알림으로 전송해서는 안 된다.

## 결정

- Web Push는 브라우저 Push API, Service Worker와 Notifications API를
  사용하고 `userVisibleOnly: true`로 구독한다.
- VAPID는 P-256 키 쌍을 사용한다. 공개키는 인증된 지원 기기에 제공하고
  개인키는 런타임 환경변수로만 주입한다.
- VAPID 개인키, Push endpoint, `p256dh`와 `auth` 값은 Git, 로그와
  클라이언트 오류 메시지에 기록하지 않는다.
- 서버는 VAPID 키가 없을 때 Push 기능만 비활성화하고 대시보드의 다른
  기능은 계속 제공한다.
- 구독은 기기 레코드에 연결한다. 한 기기는 활성 구독 하나를 가지며 새
  구독 등록은 기존 값을 교체한다.
- 부모 모바일은 기본적으로 Push를 사용할 수 있다. 공용 태블릿은 명시적
  선택 시에만 허용하고 TV와 신뢰 PC는 구독 API를 사용할 수 없다.
- 구독 등록·교체·해지는 유효한 기기 인증, 동일 Origin 요청과 제한된 JSON
  본문을 요구한다.
- 기기 폐기 시 해당 기기의 Push 구독도 같은 트랜잭션에서 폐기한다.
- Push 서비스가 `404` 또는 `410`을 반환하면 만료된 구독으로 처리해
  서버에서 폐기한다.
- 실제 일정·할 일 발송은 E4 도메인 모델과 공개 범위 필터가 준비된 후
  연결한다. E3에서는 가족 데이터를 포함하지 않는 테스트 알림만 사용한다.

## 키 운영

- 키는 앱이 시작할 때 자동 생성하지 않는다. 무인 재시작이나 컨테이너
  재생성으로 발신자 신원이 바뀌는 것을 막기 위해 운영자가 한 번 생성한다.
- Synology 배포에서는 권한이 제한된 `.env`에 VAPID 키를 저장하고 Compose
  환경변수로 주입한다.
- 개인키 분실 또는 의도적 회전 시 기존 Push 구독은 재사용하지 않고 각
  부모 모바일에서 다시 구독한다.
- 현재 외부 백업 절차가 연기되어 있으므로 개인키는 운영 전 별도 비밀
  저장소에도 보관한다. 실제 값이나 저장 위치는 프로젝트 문서에 기록하지
  않는다.

## API 경계

| 메서드 | 경로 | 용도 |
|---|---|---|
| `GET` | `/api/push/config` | 지원 여부, VAPID 공개키와 현재 기기의 구독 상태 |
| `PUT` | `/api/push/subscription` | 현재 기기의 구독 등록 또는 교체 |
| `DELETE` | `/api/push/subscription` | 현재 기기의 구독 폐기 |
| `POST` | `/api/push/test` | 현재 부모 모바일에 비민감 테스트 알림 발송 |

테스트 발송은 E3 실기기 시험용이며 관리자 모드에서만 노출한다.

## 근거

- W3C Push API는 구독을 Service Worker scope와 연결하고 endpoint,
  `p256dh`, `auth` 키를 구독 정보로 정의한다.
- RFC 8292는 VAPID 발신자 키로 P-256 ECDSA를 사용하도록 정의한다.
- 기기별 구독은 기존 E2의 기기 인증·폐기 경계와 일치하며 별도 가족 계정
  모델을 미리 도입하지 않는다.

## 결과

- 부모 모바일 교체·분실 시 기기 폐기만으로 앱 접근과 Push 수신을 함께
  중단할 수 있다.
- VAPID 키를 운영 비밀로 별도 관리해야 한다.
- 키를 잃으면 부모 모바일에서 알림을 다시 활성화해야 하지만 일정·할 일
  데이터 자체에는 영향이 없다.
