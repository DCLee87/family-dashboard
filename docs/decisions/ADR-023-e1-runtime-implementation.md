# ADR-023: E1 런타임 구현 세부 결정

- 상태: 승인, Mac 로컬 및 NAS 실행 검증 필요
- 결정일: 2026-07-24

## 배경

ADR-022가 React 정적 화면, Go 단일 프로세스와 SQLite를 E1 기술 스택으로 정했다. 실제 골격을 재현 가능하게 만들려면 SQLite 드라이버, 정적 파일 포함 방식, 상태 확인과 컨테이너 권한을 구체화해야 한다.

## 결정

- SQLite는 CGO가 필요 없는 `modernc.org/sqlite`를 사용해 amd64 Linux 정적 빌드를 단순화한다.
- Vite 결과물을 Go `embed`로 실행 파일에 포함하며 런타임에는 Node.js와 별도 정적 파일 볼륨을 두지 않는다.
- SQLite 연결은 E1의 단일 쓰기 성격에 맞춰 한 개로 제한하고 WAL, 외래 키와 5초 busy timeout을 설정한다.
- `/api/health`는 프로세스와 DB 연결 상태만, `/api/runtime`은 버전·가동 시간·누적 시작 횟수만 반환한다.
- `--check-db`는 무결성만 검사하며 누적 시작 횟수를 증가시키지 않는다.
- 컨테이너는 scratch 이미지, UID/GID `10001`, 읽기 전용 루트 파일시스템과 `no-new-privileges`를 사용한다.
- Compose의 호스트 포트 `8080`은 E1 내부망 검증 전용이며 인터넷에 공개하지 않는다.

## 결과

- 프런트엔드와 백엔드가 하나의 실행 파일과 컨테이너 이미지로 배포된다.
- NAS 볼륨은 UID `10001`의 쓰기 권한을 사전에 준비해야 한다.
- scratch 이미지에는 셸과 진단 도구가 없으므로 상태 확인은 실행 파일의 `--check-db`와 HTTP endpoint를 사용한다.
- Go는 공식 임시 도구체인으로 로컬 검증할 수 있지만 Docker 이미지와 Compose는 Docker가 있는 환경에서 확인해야 한다.
