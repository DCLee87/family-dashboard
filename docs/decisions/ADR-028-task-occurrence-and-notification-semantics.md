# ADR-028: 할 일 회차와 알림 처리 의미론

- 상태: 승인
- 결정일: 2026-07-29

## 배경

ADR-013은 반복 할 일의 회차별 완료·건너뛰기를, ADR-014는 마감 유형별
기본 알림과 중요 할 일 재알림을 승인했다. 구현을 위해서는 회차 생성
시점, 서버 중단 중 누락 회차, 완료 취소 후 지난 알림과 중복 Push의
처리를 확정해야 한다.

## 결정

### 회차 날짜와 식별

- 반복 할 일의 규칙은 시스템 시간대의 현지 날짜를 기준으로 계산한다.
- 회차 키 `occurrence_key`는 규칙이 생성한 원래 현지 날짜다.
- 매일 반복은 시작일부터 포함 종료일까지 매일, 매주 반복은 선택한 ISO
  요일에 회차를 만든다.
- 마감일·시각이 있는 반복 할 일은 회차 날짜에 원본의 현지 마감 시각을
  결합한다.
- 일회성 할 일도 내부적으로 하나의 회차를 사용해 완료·알림 흐름을
  반복 할 일과 통일한다.

### 지연 생성과 복구

- 무기한 반복의 모든 미래 회차를 미리 저장하지 않는다.
- 보기 범위, 알림 예약 범위 또는 사용자 작업에 들어온 회차만 필요할 때
  영속화한다.
- 예약 작업은 시스템 시간대 날짜가 바뀔 때 당일 회차와 알림 예약에
  필요한 가까운 미래 회차를 만든다.
- 처리 완료 날짜를 영속적인 watermark로 저장한다.
- 서버가 중단됐다가 시작되면 watermark 다음 날짜부터 오늘까지 회차를
  순서대로 생성해 누락된 미완료 회차를 보존한다.
- 긴 중단 기간도 조용히 건너뛰지 않고 작은 트랜잭션 묶음으로 처리한다.
  처리 중에는 마지막 완료 watermark만 전진시킨다.
- 원본 생성일보다 이른 회차와 시스템 최초 설정 전 회차는 만들지 않는다.

### 완료·건너뛰기와 기한 지남

- 회차 상태는 `pending`, `completed`, `skipped` 중 하나다.
- `overdue`는 저장 상태가 아니라 현재 시각, 마감과 `pending` 상태로
  계산한다.
- 완료는 완료 UTC 시각과 수행 기기 ID를 기록하고 남은 알림을 취소한다.
- 완료 취소는 회차를 `pending`으로 되돌리고 완료 시각·기기를 지운다.
- 완료 취소 시 원래 알림이 아직 미래면 다시 예약한다.
- 이미 지난 일회성 알림은 즉시 재발송하지 않는다. 중요하고 기한 지난
  회차는 다음 시스템 시간대 오전 9시 재알림부터 참여한다.
- 건너뛴 회차는 완료로 세지 않고 알림과 기한 지남 계산에서 제외한다.

### 알림 작업과 발송

- 알림 정의는 할 일 또는 일정 원본에 수신자와 상대·고정 시점을 저장한다.
- 실제 발송 작업은 최종 회차 시각과 알림 정의로 계산해 영속화한다.
- 발송 작업의 고유 키는 `대상 종류 + 회차 키 + 알림 정의 + 기기`다.
- 일정 회차 변경, 할 일 마감 변경, 완료·취소, 기기 폐기와 구독 해지는
  아직 발송하지 않은 작업을 같은 트랜잭션 또는 재조정 작업으로
  취소·재계산한다.
- 예약 작업은 `pending` 작업을 선점한 뒤 발송하고 성공·영구 실패·재시도
  상태를 기록한다.
- 네트워크 실패는 제한된 지수 지연으로 재시도한다. Web Push는 전송
  특성상 완전한 정확히 한 번 표시를 보장하지 않으므로 서버 고유 키로
  중복 발송 가능성을 최소화한다.
- 만료·폐기된 Push 구독은 즉시 비활성화하고 같은 기기의 후속 작업을
  취소한다.

### 민감정보

- 부모 전용 일정 알림은 저장된 알림 작업에도 잠금 화면용 비민감 템플릿
  식별자만 사용한다.
- 발송 시에도 공개 범위 투영 서비스를 통과하며 제목·장소 원문을 작업
  오류나 로그에 기록하지 않는다.
- 할 일 알림은 지정 수신자 기기에만 작업을 만들고 기기 폐기 후 다른
  기기로 자동 전송하지 않는다.

## 결과

- 서버 중단 중 발생한 반복 할 일 회차가 사라지지 않는다.
- 무기한 반복 때문에 미래 행이 무제한 생성되지 않는다.
- 완료·취소·마감 변경과 알림 작업의 관계를 재현 가능하게 시험할 수 있다.
- 중복 Push 표시 가능성은 남지만 서버 측 중복 작업과 무제한 재시도는
  방지한다.

## 후속 확인 사항

- 회차·알림 선행 생성 범위와 예약 작업 주기는 Construction 성능 시험에서
  조정한다.
- 장기간 중단 후 복구 중 UI에 진행 상태를 보여줄지는 운영 프로토타입에서
  결정한다.
