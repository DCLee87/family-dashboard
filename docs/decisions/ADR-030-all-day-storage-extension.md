# ADR-030: 종일 일정의 호환 저장 확장

- 상태: 승인
- 결정일: 2026-08-07

## 배경

운영 중인 C1 `schedules` 테이블은 시간 일정만 허용하는 제약과 여러 자식
테이블의 외래 키를 가진다. 종일 일정을 추가하기 위해 부모 테이블을 통째로
재작성하면 기존 일정, 참여자, 반복 규칙과 회차 예외를 동시에 옮겨야 하므로
NAS 운영 데이터의 migration 위험이 커진다.

## 결정

- 기존 `schedules` 행은 공통 제목·공개 범위·참여자·감사 정보와 날짜 조회용
  UTC 경계를 계속 가진다.
- 종일 일정은 1:1 확장 테이블 `schedule_all_day_dates`에 시스템 시간대의
  포함 `start_date`, `end_date`를 추가로 저장한다.
- 확장 행이 있으면 도메인과 API의 `timeKind`는 `all_day`, 없으면 `timed`로
  해석한다.
- 반복 종일 일정의 특정 회차 날짜 변경은 회차 예외를 재작성하지 않고
  `schedule_occurrence_all_day_overrides` 1:1 확장 행으로 저장한다.
- 종일 일정의 내부 UTC 경계는 시작일 자정부터 종료일 다음 날 자정까지이며,
  API에는 이 경계를 노출하지 않고 포함 날짜만 반환한다.
- 명시적 상태 반영 구간이 없는 종일 일정은 겹침과 가족 예상 상태 계산에서
  제외한다.

## 결과

- 기존 운영 테이블과 외래 키를 재작성하지 않고 schema version 7로
  전진 migration할 수 있다.
- 여러 날 일정은 양끝 날짜를 포함하는 일별 조회가 가능하다.
- 논리 모델과 물리 저장 구조가 다르므로 저장소 밖에서는 반드시 `timeKind`와
  날짜 필드를 사용해야 한다.
