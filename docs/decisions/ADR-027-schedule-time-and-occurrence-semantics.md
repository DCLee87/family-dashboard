# ADR-027: 일정 시간과 반복 회차 의미론

- 상태: 제안
- 결정일: 2026-07-29

## 배경

ADR-004는 매주 반복과 특정 회차 예외를, ADR-005는 겹치는 일정의 상태
우선순위를, ADR-009는 종일·여러 날 일정을 승인했다. 구현 전에 다음
경계가 결정되어야 같은 데이터가 API, 화면과 상태 계산에서 동일하게
해석된다.

- 종료 시각에 맞닿은 두 일정의 겹침 여부
- 여러 날 종일 일정의 종료일 포함 여부
- 반복 회차가 어떤 날짜와 시간대를 기준으로 생성되는지
- 이동된 반복 회차를 이후 수정·취소할 때 사용하는 식별자
- 시작 시각이 같은 활성 일정의 최종 동률 규칙

## 결정

### 시스템 시간대와 저장

- 가족 시스템은 IANA 시간대 ID 하나를 가지며 초기값은
  `Asia/Seoul`이다.
- 시간 일정의 실제 시작·종료 시각은 UTC 시각으로 저장하고 API에서는
  RFC 3339 형식으로 전달한다.
- 매주 반복 규칙은 UTC 시각이 아니라 시스템 시간대의 현지 날짜, 현지
  시작 시각과 현지 종료 시각으로 저장한다.
- 사용자가 입력한 현지 시각을 UTC로 변환할 수 없거나 한 시각이 둘로
  해석되는 시간대 전환 구간에서는 저장을 거부하고 명시적인 오류를
  반환한다. 임의로 보정하지 않는다.
- 생성·수정·삭제 시각과 감사 시각은 모두 UTC로 저장한다.

### 시간 일정 구간

- 시간 일정은 시작을 포함하고 종료를 제외하는 반개구간
  `[start, end)`으로 해석한다.
- 종료 시각은 시작 시각보다 반드시 늦어야 한다.
- 한 일정의 종료와 다른 일정의 시작이 같은 경우 두 일정은 겹치지
  않는다.
- 자정을 넘는 시간 일정은 하나의 연속 구간으로 저장할 수 있다.

### 종일 일정 날짜

- 종일 일정은 `start_date`와 `end_date`를 시스템 시간대의 달력
  날짜로 저장하며 양끝 날짜를 모두 포함한다.
- `end_date`는 `start_date`보다 빠를 수 없다.
- 단일 날짜 종일 일정은 두 날짜를 같은 값으로 저장한다.
- 종일 일정은 날짜별 화면에는 포함하지만, 별도의 상태 반영 구간이
  없으면 예상 상태 계산에서는 제외한다.
- 선택적인 상태 반영 구간은 일반 시간 일정과 동일한 UTC 반개구간으로
  저장한다.

### 반복 회차와 예외

- 반복 원본은 시스템 시간대의 시작일, 선택 요일, 선택 종료일, 현지
  시작·종료 시각을 가진다.
- 반복 종료일은 포함한다. 종료일이 없으면 명시적인 무기한 값으로
  저장한다.
- 회차 키 `occurrence_key`는 반복 규칙이 원래 생성한 현지 시작
  날짜·시각을 정규화한 문자열이다.
- 특정 회차의 시간이 변경되어도 회차 키는 원래 값으로 유지한다.
- 회차 예외는 하나의 원본과 회차 키 조합에 최대 하나만 존재하며
  `cancelled` 또는 `overridden` 상태를 가진다.
- 원본 반복 규칙을 수정하면 과거 예외는 자동 이동하지 않는다. 수정된
  규칙에서 더 이상 생성되지 않는 회차의 예외는 저장을 거부하거나
  관리자에게 충돌로 제시해야 하며 묵시적으로 삭제하지 않는다.

### 겹침과 예상 상태 동률

- 겹침 검사는 삭제되지 않은 최종 회차와 일회성 일정을 펼친 결과에
  대해 대상 가족별로 수행한다.
- 같은 가족에게 활성 장소 일정이 여러 개면 ADR-005에 따라 실제 시작
  시각이 가장 늦은 일정을 선택한다.
- 실제 시작 시각도 같으면 다음 순서로 하나를 선택한다.
  1. 종일 일정의 명시적 상태 반영 구간
  2. 반복 원본보다 단일 회차 변경
  3. 더 나중에 생성된 일정
  4. 문자열 ID 오름차순
- 동률 규칙과 무관하게 겹친 모든 일정과 겹침 표시는 유지한다.
- 권한 없는 응답에는 선택에 사용된 민감한 제목, 장소 또는 메모를
  포함하지 않고 ADR-006의 비식별 상태만 반환한다.

## 결과

- API, SQLite 조회와 화면이 같은 경계 규칙을 사용할 수 있다.
- 반복 일정은 시스템 시간대가 바뀌거나 일광 절약 시간제가 있는
  시간대로 확장되어도 현지 생활 시각을 유지한다.
- 이동된 회차를 원래 회차 키로 안정적으로 다시 수정하거나 취소할 수
  있다.
- 동률 선택은 서버 재시작이나 조회 순서에 따라 바뀌지 않는다.
- 시스템 시간대 변경은 기존 반복 일정의 의미를 바꿀 수 있으므로 초기
  버전에서는 설정 후 변경 기능을 제공하지 않는다.

## 검토가 필요한 사항

- 같은 시작 시각의 동률 규칙이 실제 가족 사용 방식과 맞는지 E4
  프로토타입에서 확인한다.
- 반복 원본 수정 시 이미 생성된 예외 충돌을 사용자에게 어떻게
  해결하게 할지는 Construction UI 설계에서 확정한다.
