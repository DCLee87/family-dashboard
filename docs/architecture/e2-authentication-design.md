# E2 기기 인증과 관리자 모드 설계

- 상태: 기준선 초안
- 작성일: 2026-07-26

## 보안 경계

- Tailscale은 외부 네트워크 접근을 제한한다.
- 앱 기기 인증은 가족 데이터 접근을 제한한다.
- 관리자 PIN은 인증된 기기 안에서 변경 권한을 일시적으로 잠금 해제한다.
- 세 경계 중 하나를 통과했다고 다른 경계를 생략하지 않는다.

## 자격정보

| 종류 | 원문 전달·저장 | 서버 저장 | 수명 |
|---|---|---|---|
| 초기 설정 코드 | 운영 로그에 한 번 표시 | SHA-256 해시 | 10분, 일회 사용 |
| 등록 코드 | QR·대체 코드로 한 번 표시 | SHA-256 해시 | 10분, 일회 사용 |
| TV 6자리 코드 | TV에 표시 | SHA-256 해시 | 10분, PC 최종 승인 필수 |
| 기기 토큰 | HttpOnly 쿠키 | SHA-256 해시 | 30일, 자동 회전 |
| 갱신 토큰 | HttpOnly 쿠키 | SHA-256 해시와 계열 ID | 90일, 매 사용 회전 |
| 관리자 세션 | HttpOnly 쿠키 | SHA-256 해시 | 10분 유휴, 최대 1시간 |
| PIN | 입력 순간만 메모리 | Argon2id PHC 문자열 | 변경 전까지 |
| PIN 복구 코드 | 한 번 표시 | SHA-256 해시 | 일회 사용 |
| CSRF 토큰 | 응답과 요청 헤더 | 세션 결합 SHA-256 해시 | 세션과 동일 |

모든 난수 토큰은 Go `crypto/rand`로 최소 128비트 엔트로피를 생성한다. 기기
토큰과 갱신 토큰은 256비트를 사용한다. 비밀번호처럼 엔트로피가 낮은 PIN만
느린 비밀번호 해시를 사용하며, 충분한 난수 토큰은 빠른 단방향 해시와
상수 시간 비교를 사용한다.

## PIN

- 숫자 4자리 형식은 기존 ADR을 유지한다.
- Argon2id의 초기 파라미터는 메모리 19MiB, 반복 2회, 병렬도 1, salt
  16바이트, 출력 32바이트다.
- 알고리즘, 버전과 파라미터를 PHC 문자열에 함께 저장해 향후 상향한다.
- DS216+II에서 해시 시간을 측정하고 정상 입력이 과도하게 느리면 동등한
  OWASP 권고 조합 안에서 조정한다.
- 기기별 5회 연속 실패 후 5분 차단한다.
- 성공 시 해당 기기의 실패 횟수를 초기화한다.
- 관리자 세션은 마지막 관리자 요청 후 10분, 발급 후 최대 1시간에
  만료한다.

## 기기 유형과 권한

| 유형 | 네트워크 | 보기 | 관리자 PIN | 기기 승인·복구 |
|---|---|---|---|---|
| 신뢰 PC | 로컬·외부 | 허용 | 허용 | 허용 |
| 부모 모바일 | 로컬·외부 | 허용 | 허용 | 거부 |
| 공용 태블릿 | 로컬 전용 | 허용 | 허용 | 거부 |
| TV | 로컬 전용 | 허용 | 거부 | 거부 |

권한은 클라이언트가 보낸 유형이 아니라 서버 DB의 기기 레코드로 판정한다.

## 쿠키

- 외부 HTTPS에서는 `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`를
  적용한다.
- 개발용 HTTP 허용은 명시적인 개발 설정에서만 가능하며 운영 기본값은
  Secure다.
- 자격정보를 `localStorage` 또는 URL에 저장하지 않는다.
- 상태 변경 요청은 허용 Origin 검사와 세션에 결합된 CSRF 헤더를 모두
  요구한다.

## 네트워크 판정

- 기본적으로 소켓의 `RemoteAddr`만 신뢰한다.
- 가정 내 네트워크 CIDR은 설정으로 명시하며 기본 운영값을 소스에
  하드코딩하지 않는다.
- `Forwarded`와 `X-Forwarded-For`는 명시된 신뢰 프록시 CIDR에서 온
  요청에만 사용한다.
- Tailscale Serve의 loopback 요청은 외부 사설망 요청으로 분류하고 로컬
  등록 권한을 부여하지 않는다.
- Tailscale 신원 헤더가 직접 LAN 요청에 포함돼도 무시한다.

## 갱신과 폐기

- 갱신할 때 이전 토큰을 소비하고 새 토큰을 발급한다.
- 제한된 중복 요청 허용 시간이 필요하면 최대 60초로 하고 동일한 새 토큰
  결과만 반환한다.
- 소비된 갱신 토큰이 다시 사용되면 해당 토큰 계열 전체를 폐기한다.
- 기기 폐기는 액세스·갱신·관리자 세션과 Push 구독을 한 트랜잭션에서
  무효화한다.
- 다른 기기의 자격정보에는 영향을 주지 않는다.

## 감사

다음 이벤트의 시각, 기기 ID, 결과와 일반화된 원인을 기록한다.

- 초기 설정 성공·실패
- 등록 요청·승인·거절·만료
- PIN 성공·실패·차단
- 토큰 갱신·재사용 탐지
- 관리자 모드 잠금·해제
- 기기 폐기
- 권한·Origin·CSRF·네트워크 정책 거부

PIN, 토큰, 코드, 쿠키, 실제 주소와 가족 데이터는 기록하지 않는다.

## SQLite 엔터티

- `security_state`: 초기 설정 완료 여부와 PIN 해시
- `devices`: 유형, 소유자, 로컬 전용, 상태, 마지막 사용
- `device_credentials`: 토큰 해시, 계열, 만료, 소비·폐기 시각
- `enrollment_requests`: 코드 해시, 유형, 상태, 만료와 승인 기기
- `admin_sessions`: 세션·CSRF 해시, 유휴·절대 만료와 폐기 시각
- `pin_attempts`: 기기별 실패 횟수와 차단 종료
- `recovery_codes`: 복구 코드 해시와 소비 시각
- `security_events`: 비밀을 포함하지 않는 제한된 감사 이벤트

## 구현 순서

1. 난수·해시·PIN 패키지와 단위 테스트
2. SQLite 마이그레이션과 제약조건
3. 최초 설정 상태와 로컬 네트워크 게이트
4. 기기 인증 미들웨어와 기본 거부 API
5. 등록·승인·폐기
6. PIN 관리자 세션과 요청 제한
7. 토큰 회전·재사용 탐지
8. NAS와 실제 기기 검증
